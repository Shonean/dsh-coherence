Coherence 前端手册

Coherence 是 dsh 的多 agent 协作与记忆套件：转录摄取、三层记忆、代码库地图、共享工作日志，以及一个把这一切暴露给外部 agent 的 MCP 桥。本手册讲它的三个前端表面——Coherence 页签、会话里的委派卡片、插件包页签——怎么读、怎么点、出了问题怎么查。

版本 0.1.1-rc.2 界面 DSH Desktop / 内嵌 SPA 更新 2026-08-31

00总览：三个表面，一份数据

所有表面读的是同一份存储。你在 Hub 里看到的接入状态，就是 MCP 桥喂给外部 agent 的同一批转录；插件包页签停用的，也是同一条链路。知道这一点，查问题时就不会迷路。

表面位置管什么
Coherence 页签会话顶部页签环（对话 · 轨迹 · Coherence）外部 agent 接入状态、子 agent 血缘、三层记忆浏览与检索
委派卡片消息流里每次子 agent 委派一行单次委派的生命周期、提示词与结果
插件包页签设置 → 插件 → 插件包按包分组查看插件、停用/启用整个 coherence 家族

01打开 Coherence 页签

打开（或新建）一个会话，发过第一条消息之后，会话标题下方会出现页签环：

[ 对话 ] [ 轨迹 ] [ Coherence ]

点 Coherence 进入。整个视图不依赖某条会话——记忆和接入状态是跨会话的全局数据——但页签本身挂在有内容的会话里。

注意刚新建的空白会话不会显示页签环，这是所有会话视图的统一行为；发一条消息（或切到有历史的会话）就会出现。

03Memory 分区

三层记忆沿用了 CLS 的思路——记忆是会被改写的，不是只增不减的日志。三层各司其职：

working工作记忆当前会话的事实、观察、决定、待办
episodic情节记忆一次会话/子 agent 运行蒸馏出的一段经历
semantic语义记忆巩固出的长期断言，带主题与置信度

episodic ──巩固作业──▶ semantic

三层各自记什么、谁来写

层典型内容谁写入生命周期
working 四类条目：事实 / 观察 / 决定 / 待办 agent 的 memory_write 工具、外部 agent 经 MCP、摄取时的 feedMemory 开关 会话级——最活跃也最短命，随时被更新的条目改写
episodic 一段经历：摘要 + 带时间戳的事件序列（用户/助手/工具/决策）+ 起止时间 会话或子 agent 运行结束时蒸馏生成 沉淀留存，是巩固作业的原料
semantic 断言：主题 + 论断 + 置信度 + 证据来源计数 巩固作业从情节层提炼；也可直接写入 长期。同主题新断言会推翻旧的（见下）

记忆会被改写：四种状态

CLS 的核心观察是「回忆即重写」。这里没有删除——被取代的记录只是标记状态，并用 supersededBy 指向取代它的那条，历史永远可追溯：

  • 有效（active）——当前可信；检索默认只返回这一类。
  • 已过时（outdated）——被新条目取代（新知识覆盖旧知识）。
  • 已矛盾（contradicted）——同主题来了一个冲突的语义断言：旧断言标「已矛盾」，新断言以「待定」身份入库，直到被再次证实。
  • 待定（tentative）——新写入、尚未证实的断言。

巩固作业：情节如何变成语义

后台定时巩固（默认每小时检查一次）：情节层条目数超过阈值（默认 20）时，把每条有效情节蒸馏成语义断言——主题取来源 agent，置信度随证据积累，同一主题的重复断言合并（证据计数 +1）。也可以随时用 memory_consolidate 手动触发。

语义检索

输入关键词点 检索，走的是记忆服务的预算排序器：按相关度打分，按三层各自的预算配额截断，只返回「有效」状态的记录（已过时/已矛盾的默认不参与）。

说明当前版本读取的是默认（legacy）工作区分片——和 MCP 工具的默认范围一致。如果你在多工作区隔离的场景下写入了其他分片，这里的计数不会包含它们；按工作区切换在路线图上。

还没开放的分区

后续 页签是声明过的占位：代码库地图、工作日志、跨 agent 转录搜索会以同样的方式进来，数据侧（服务与存储）已经就绪。

04会话里的委派卡片

主 agent 每次委派子 agent，消息流里落一行卡片。状态只从持久化的调用/结果推导——回放历史会话时状态不会变，哪怕实时目录早就翻篇了。

状态长什么样说明
running标题带扫光动画子 agent 正在跑
ok模型自拟的 3–5 词任务标签正常结束
error首行错误信息替换标签运行失败
stopped警告态被中止
  • 后台运行（run_in_background: true）的委派带 后台 徽标。
  • 整行可展开（回车/空格也可以），展开后是原样的委派提示词和结果文本。
  • 卡片右侧的 Inspect 进入轨迹检查器，看这次调用的耗时与用量。

05插件包页签：启停整个家族

路径：设置 → 插件 → 插件包。这里把当前加载的插件按包分组，coherence 家族（coherence + 三个浏览器半）聚在一组，组头一个开关。

  • 停用是原地生效的：Loader 运行时卸载，内核不重启；成功后整页刷新，你会看到前端退回原生形态（Coherence 页签消失、委派卡片退回通用渲染、MCP 3140 下线）。
  • 状态持久化在 ~/.dsh/cordis.patch.yml，重启后依然生效。
  • 再启用同样原地完成，一切恢复。
设计保证插件包页签本身（ui-coherence-inventory）永远不可被停用——它是你重新启用一切的那把钥匙。

06外部 agent 通道

前端之外的三个读数入口，给 MCP 客户端和人类：

  • MCP 桥（features.mcpServer）：streamable-http，默认地址——

http://127.0.0.1:3140/mcp

  • 十二个工具：memory_write / recall / forget / status / consolidate、codebase_map_save / get / list、worklog_get_direction / update_direction / log / list。
  • 文件镜像：~/.dsh/mirror/ 下的 DIRECTION.md、memory-*.md、codebase-map.md 等，人类可读。
  • MCP 与前端是并列的两条读路，写进去的数据（比如经 MCP 写的一条记忆）刷新 Hub 后立刻可见。

08疑难解答

Coherence 页签不见了

按顺序查：① 会话是空白的——发条消息或切到有历史的会话；② 启停时停过 coherence 家族——去 插件包 页签重新启用；③ features.webGateway 被关了——打开它。

Memory 计数是 0，但我明明写过

确认写入走的是哪个分片。Hub 和 MCP 默认读 legacy 分片；多工作区场景写入的命名分片这里看不到。另外记忆条目若已是「已过时/已矛盾」，检索默认不会返回它们，但列表（全部/对应层）仍会列出。

启动时报 "entry did not activate … waiting for service: remote.pluginControl"

打包产物里的运行时闭包过期了（前端是新代码、闭包里的服务组装是旧版）。用当前仓库重新打包桌面端即可——构建脚本的 afterPack 钩子现在无条件按仓库源刷新工作区包，不会再出「旧但完整」的拷贝。

把 coherence 停用后，设置页签还在吗

在。插件包页签自身被设计为不可停用，随时可以进去把家族再打开。极端情况下也可以手工删掉 ~/.dsh/cordis.patch.yml 里对应的行（或整个清成 []）后重启内核。

接入卡片一直是灰点

对应来源的特性开关没开（ingestOpencode / ingestCodex 默认关），或者该工具的存储路径上还没有任何会话。Claude Code 开箱即摄——跑过就会有数。
